## 一、统一中间表示：参数卡

两侧输入（文献表 / 论文正文）都解析成参数卡，审计问题归约为**结构化对齐**。

### 1.1 文献条目卡 RefCard（REF-01 产出）

```json
{
  "card_id": "ref-000001",
  "entry_type": "J",                    // GB/T 7714 文献类型标识：J/M/D/C/N/R/P/S/DB/OL/A…
  "authors": [{"family": "张", "given": "三", "raw": "张三"}],
  "title": "论文题名",
  "source": {"container": "计算机学报", "year": "2024", "volume": "47",
              "issue": "5", "pages": "101-110", "publisher": null, "city": null},
  "identifiers": {"doi": "10.9999/fake.2024.001", "isbn": null, "url": null},
  "evidence": {"src": "refs.txt", "offset": 0, "raw": "原始整行文本"},
  "confidence": 0.97,
  "flags": ["hyphen_break_repaired", "fullwidth_punct_normalized"]
}
```

- `confidence`：分层噪声下逐条计算（字段齐+证据完整=高；修复性 flag 越多越低）；
- 低置信度字段**宁缺**：宁可缺失留给 manual_confirm，不得猜值硬填。

### 1.2 论文对象卡 DocObjectCard（M2 论文解析器产出）

```json
{
  "card_id": "obj-000001",
  "kind": "figure",                     // figure | table | equation | chapter | citation_marker
  "label": "图3",                        // 归一化标签（全半角/空格伪影已清洗）
  "anchor": {"para_index": 142, "style": "Normal", "is_ref_field": false},
  "mentions": [{"para_index": 210, "mode": "handwritten", "raw": "如图 3 所示"}],
  "caption_span": null
}
```

## 二、规则包与条款库 schema

条款库（`data/knowledge/`）与规则包（`data/rulesets/`）同一纪律：**每条挂出处，无 status 不得生效**。

```json
{
  "rule_id": "GBT7714-2015-punct-01",
  "scope": "reference.format",
  "standard": "GB/T 7714-2015",
  "clause": "示例：著录标点（具体条号入库时以原文核对）",
  "quote": "条款原文逐字摘录（≤125 字/引，WebFetch 通道实测上限）",
  "status": "verified | pending",       // pending=待核对：可展示、不生效、不进判定
  "severity": "error | warn | info",
  "check_type": "field_required | punct | page_range | author_threshold | consistency | ...",
  "detect": {"param": "...", "op": "...", "value": "..."},
  "fix": {"type": "auto | suggest", "template": "..."},
  "only_if_text": ["关键词门控"],        // 类目隔离门控，对全部 check_type 生效
  "gates": {"standard_year": ["2015", "2025"], "profile": ["default", "school-*"]}
}
```

四层 ruleset 叠加顺序：**国标版（2015/2025 双标尺）→ 年份版 → 期刊 profile → 学校模板 profile**，后层只做增量覆盖，覆盖动作留审计痕迹（迁移清单是 2025 版双标尺的展示面）。

## 三、三级判定与证据链

```json
{
  "rule_id": "...",
  "status": "pass | fail | manual_confirm",
  "evidence": {"clause": "条号", "quote": "原文摘录", "location": {"doc": "...", "para": 0, "span": [0, 0]}},
  "suggestion": "修正建议（auto 项带 diff）",
  "confidence": 0.0
}
```

- 多值解析/低置信度 → `manual_confirm`，**不硬判**；"待人工确认"在报告中为独立级别；
- 数值结论只来自确定性规则；报告首部强制免责声明（模板硬编码）。

## 四、四类标记体系解析（FULL-01 前置）

| 维度 | 取值 |
|---|---|
| 对象类型 | 图 / 表 / 公式 / 章节 |
| 标记模式 | Word REF 域（instrText 含 REF）| 手打编号（正则，清洗全半角与空格伪影） |
| 审计目标 | 悬空标记（提及相关对象不存在）、幽灵对象（对象从未被提及）、乱序断档 |

工程陷阱（解析器必配回归）：多行标注按 y/x 邻近聚类合并；字符逐个定位的伪空格；CRLF 残留；中文路径；GBK 控制台。

## 五、编号重排内核（REF-07 与 FULL-01 共用）

```python
def renumber(items: Sequence[NumberedItem], edits: Sequence[Edit]) -> RenumberPlan:
    """NumberedItem: {item_id, order, markers: [MarkerRef]}
       Edit: {type: insert|delete, target: item_id}
       RenumberPlan: {mappings: [{marker, old_no, new_no}], consistent: bool}"""
```

- 一致性定义：重排后**正文每个标记**都能解析到唯一新编号，且编号序列连续无断档；
- 基准：任意插入/删除位置 × 组合矩阵回归 100%（M3 文献编号、M4 对象编号各一套真值）；
- 一键插入（Word/WPS COM）走同一 RenumberPlan 落回文档。

## 九、M2 解析层实现级定稿（2026-10-07，骨架级 → 实现级的差异全在此）

### 9.1 参数卡 schema 落地（对 §一 的实现化）

- **不上 dataclass/pydantic**：参数卡用 `taw.cards` 的 dict 构造器产出 + `validate_*`
  校验（core 保持零依赖到引擎前）；
- **字段补全**：`source` 增 `edition`、`report_no`（GB/T 7714 图书版次与报告号；
  骨架级漏了它们，实测导致解析器字段被构造器静默过滤）；
- **`evidence` 增 ordinal/label**：`{src, ordinal, label, raw}`——`ordinal` 是条目在
  文件中的序位（txt/ris 无 entry_id 时的对账键），`label` 是 `[n]` 编号或 bib key；
- **证据链**：`make_finding(rule_id, status, location, clause, quote, suggestion, confidence)`
  落地 §三；`status ∈ {pass, fail, manual_confirm}`，`location` 强制存在。M2 只提供
  schema 与构造器，判定引擎 M3/M4 接入；
- **DocObjectCard**：`caption_span`（骨架级）落地为 `caption: {para_index}`——
  学位论文题注为单段，无需 span；`mentions[].mode ∈ {ref_field, handwritten}`。

### 9.2 文献解析器 REF-01（`taw.refparse`）

- **清洗管线顺序**（顺序敏感）：断行合并（`-\n` 去连字符）→ 全半角归一 →
  中文标点归一（，→", "、：→": "，仅文献表语料）→ 多空格压缩 → CJK 字间空格清除 →
  年份断字修复（`20 24`→`2024`）。每个修复记 flag，confidence 按 flag 扣减；
- **噪声 flag 只记真跨行的条目**：分条先在**原始行**上按条目边界切，再对每条自己的
  行做合并——否则"文件有多行"会被误报为噪声，clean 文件 confidence 被系统性压低
  （实测踩坑，bib/ris 尤其严重，故对结构行 `@type{`/`XX  - ` 单独识别）；
- **body 段语义按结构推断，不信文献类型标识**：`//`→C、报告号→R、版次段→M、
  卷期段→J——类型标识错误是 M1 注入的审计缺陷（M3 finding），解析器用它会导致
  字段分派错误（实测：误标 C 的 J 条目 body 全错）；
- **宁缺纪律量化**：分支不匹配 → 字段 None + `body_unparsed_segment` flag；
  confidence 扣减 = 修复 flag ×0.02 + 缺期望字段 ×0.08 + 无类型标识 ×0.15；
- **ris 伪影**：M1 生成器把缺失字段渲染为字面 `"None"`（`CY  - None`）→ 解析器
  归一为缺失 + `ris_none_value_artifact`（**不改冻结数据**，按"已知伪影"记档）；
  ris 标签可被噪声劈开（`A U  - `/`A\nU  - `）→ 容错正则 + 碎片预合并。

### 9.3 论文解析器（`taw.thesisparse`）

- **style_tree 走 python-docx `.text`**：`fldSimple` 内 run 不计入（与 M1 真值一次
  锁定的口径一致，测试断言 `field.display not in para.text`）；
- **域解析**：段落内 `w:fldSimple` 的 `w:instr`（`REF <bookmark> \h`）+ 文档 XML
  书签全集 → `bookmark_exists`；域显示文本单独取（不进 `.text`）；
- **对象识别**：题注段 = Caption 样式 **或** 整段以"图/表+编号"开头**且无句读标点**
  （后一条防"表4-1给出…，式(4-1)…"这类正文段被误判为题注——实测踩坑）；
  公式 = 段尾 `（n-m）` 编号；
- **标记**：正文正则找手打编号（全半角破折号归一、伪空格清除）+ 域显示文本；
  题注段自身编号不计为提及；公式段自身即提及；
- **悬空/幽灵**：标记无对应对象 = 悬空；对象零提及 = 幽灵。

### 9.4 F1 基准与门槛（`taw.f1bench`）

- **文献面**：逐字段对账 canonical 侧 = `data/frozen/refs/refs_logic.json`
  （生成器 post-injection 逻辑记录，作为**数据**落盘——不让 f1bench 运行期 import
  `code/tools/`，打包后 exe 也能对账）；
  门槛：**clean ≥0.99 / light ≥0.97 / heavy ≥0.95**（plan/05 M2 行锁 clean 与 heavy，
  light 为实现者裁量取中）；
- **口径裁定**：
  1. `entry_type` 不进 F1 分子分母（类型标识错误是 M3 finding），逻辑记录里保留供 M3 用；
  2. 真值声明 punct 命中本格式的条目剔除出严格 F1（标点损伤是审计素材）；
  3. **载体语义豁免**：ris 无 edition 标签、txt/csv 不渲染 edition==1 → 该字段不进分母；
  4. 著者截断（前三+等/et al）时尾部著者不计 FN（文本中确实不存在）；
  5. doi/isbn/pages/report_no 属无空格字段，构造期清除内部空白后比较；
- **论文面**：style_tree 逐段 `(style,text)` **全等**才算过；fields/objects（含
  caption_para、mentioned 集合、bookmark）按集合精确对账；悬空/幽灵按真值植入
  标签包含匹配（真值 `expect.field` 是人读描述，如 `REF _Ref99900099（图9-9）`）；
- **报告**：`taw parse` 之外由 `f1bench.write_report` 落盘 JSON（无时间戳、可重复生成），
  两 M 门槛判定写进 plan/05 与 HANDOFF（reports/ 为运行产物，不入仓）。

## 十、M3 文献线引擎实现级定稿（2026-10-07）

> 骨架级 → 实现级的差异全在此；改其中任一条 = 改口径，须同步改测试与本文件。

### 10.1 规则「条款状态」与「检测生效」正交（关键裁定）

M1 落库的四层 ruleset 规则 `status` 全为 `pending`：GB/T 7714 全文两版官方均不可得
（2015 废止不提供 / 2025 采标版权，官方声明原文在案），按纪律无法摘录原文入 `quote`。
若按字面「pending 一律不生效」，M3 的 REF-02 将零产出、DoD 无法达成；而 plan/05 对
REF-03 的表述本就是「M1 骨架 / **M3 生效**」。

故 M3 起把两件事拆成**正交双字段**（新增字段，既有语义不变）：

| 字段 | 含义 | 取值 | 决定 |
|---|---|---|---|
| `status` | **条款核对状态** | `verified` / `pending` | finding 能否引用标准条号+原文摘录作规范依据 |
| `activation` | **检测生效开关** | `active` / `gated` | 该检测是否运行 |

- `activation` 缺省时**回退** `status == "verified"` → M1 骨架口径完全兼容；
- M3 需生效的文献线规则置 `active` 并挂 `basis`（工程口径或合成真值契约），
  条款 `status` 仍保持 `pending`；
- **NFR-04 不被削弱**：findings 一律携带 `clause_status` 与 `basis`，报告层对 pending
  条款显式标注「条款待核对」，只展示工程依据，绝不伪造条号与原文摘录。
- M4 才接入的全文线规则（结构/数字/图表/ AIGC）置 `gated`。

### 10.2 REF-02 格式核查规则（逐条挂 basis，误报 0 优先）

判定原则：**只判「确定性可判」的问题；证据不充分一律 `manual_confirm`，不硬判**
（NFR-05）。以下规则经冻结数据 72 条 × 4 格式实测校准：

1. **field_required（缺项）**：必著录字段按**类型**取注入池口径
   （J=year/pages/volume；C=year/publisher/pages；D=year/city；M=year/publisher/pages；
   R=year/city），且必须同时满足两道门控——
   - **载体可表达性校准**：该字段须在本文件**同批次**其他条目中确实出现过
     （自动豁免 ris 无 edition、txt 不渲染 edition==1 这类载体语义差异）；
   - **噪声门控**：条目带断行/连字符/空格类修复 flag 时不出缺项结论（解析可能丢字段），
     `year` 因 token 短、抗噪强而豁免；
   实测：TP=30 / FP=0 / FN=0（全 72 条 × 4 格式）。
2. **type_marker（类型标识错误）**：判据 = **声明标识 vs 载体原生结构签名**不符
   （bib 字段集 / ris 标签集 / txt-csv body 结构分支），签名唯一时才出结论。
   签名按**真类型**渲染而标识按注入值渲染——两者不符即标识错误。实测 FP=0。
3. **author_threshold（著者数与"等"）**：双向可判——
   - 「列出 >3 位且无 `等`/`et al`」→ `fail`（未按前三+等截断）；
   - 「列出 <3 位却带 `等`」→ `fail`（不足阈值误加）；
   - 「恰好列出 3 位且带 `等`」→ **`manual_confirm`**：原文既可能是「3 位著者误加等」
     也可能是「≥4 位正确截断」，citation 文本**不可区分**（实测 ref-0061 vs ref-0001
     渲染串完全相同）——多值歧义不硬判。
4. **page_range（页码倒置）**：起页 > 止页 → `fail`（纯确定性）。
5. **citation_style（编码制混用）**：txt/csv 中**无 `[n]` 标签**且呈「著者, 年. 题名」
   形态的条目混入顺序编码制文献表 → 文件级 finding。
6. **punct（标点）**：M2 清洗管线会把全角标点归一（，→", "），故**标点损伤须在
   原始文本/残留 flag 上判**，不能只看 card。实测 FP=0 的信号：
   - txt/csv：`authors_title_separator_missing` flag（题名前分隔丢失）；
   - txt/csv：ASCII 逗号紧邻 CJK（",陈"）＝中文逗号残留；
   - txt/csv：末尾多余标点（"...,."）；
   - bib：`author` 字段行末缺逗号（与同块其他字段行对照）。

### 10.3 证据链与报告口径

- 所有 finding 走 `taw.engine.make_rule_finding`：三级判定 + 条款 + 位置 +
  `severity/check_type/clause_status/basis`；报告强制免责声明（NFR/边界守卫 §四.5）。
- `manual_confirm` 在报告中为**独立级别**，不与 fail 混计（NFR-05）。

### 13.3 打包：onedir 双 exe + 两条构建红线（`code/tools/`）

版本纪律：py3.8 锁 `pyinstaller>=5.13,<6`（6.x 在 3.8 上 modulegraph 随机崩）；py3.9+ 用 `>=6`。

| 工件 | 内容 |
|---|---|
| `tools/taw.spec` | onedir 双 exe：`taw.exe`（console=True）+ `taw-gui.exe`（console=False），共用同一 COLLECT 目录 |
| `tools/check_build_redline.py` | 构建红线：dist 禁区成分扫描 + 内嵌数据逐文件对账 |
| `tools/verify_neutral_dir.py` | 中立目录干净验证五连 |

**onedir 关键坑（首版踩到）**：EXE 必须 `exclude_binaries=True`，把 binaries/datas 交给
COLLECT；否则 EXE 把整包嵌进本体，产出 57MB 的**伪 onefile**（运行时解到 `_MEIxxxx` 临时
目录）。正确形态：引导壳仅 8-10MB，`dist/taw/data/` 就地可读。测试
`test_spec_is_onedir_not_onefile` 断言两个 EXE 都是 `exclude_binaries=True`。

**内嵌数据必须带 `data/README.md`**：`paths.py::_is_valid` 用它作数据根标志
（`is_dir() and (dir/'README.md').is_file()`）；漏掉它，打包后 `find_data_dir` 会判内嵌
数据无效而整体降级。`test_spec_bundles_data_readme_marker` 钉死。

**构建红线三类违例**（`scan_dist_forbidden`）：`_private/` 目录、`.db`/`.sqlite`/`.env`/`.key`
后缀、真实实体关键词（合成数据里的"虚构理工大学""李虚构"**不在黑名单**——那是刻意的虚构值，
`test_bundled_fictional_names_are_not_flagged` 防止红线误伤打包）。

**内嵌数据对账三类偏差**（`reconcile_embedded_data`，均按 SHA-256 逐文件比对）：
`missing`（漏打）/ `extra`（混入不该进包的文件）/ `mismatched`（打入旧版字节不符）。

**中立目录五连**（`verify_neutral_dir.py`）：dist 复制到**仓库树外** + **剥离 PATH**
（`PATH=""`），五条命令**逐条取真实 returncode**（不接管道——管道会吞真实状态；
`PIPESTATUS` 在 Windows 也不适用）：`selfcheck` / `demo` / `parse` / `audit refs` /
`audit bench --line all`。命令清单由 `test_neutral_cases_are_exactly_the_five_commanded` 钉死。

### 13.4 CLI 编码纪律（M6 补上的历史坑）

非 UTF-8 stdout（Windows CI 管道的 cp1252 等）会把中文输出打成 `UnicodeEncodeError`
并让整条命令崩在打印上。`cli._ensure_utf8_stdout()` 在 `main` 入口先 reconfigure
（能切 UTF-8 就切，不能则退化为 `errors="replace"`；`PYTHONIOENCODING` 已指定 Unicode
编码时不动）。`test_cli_survives_non_utf8_stdout` 用子进程复现 cp1252 环境钉死。
